# WD-01: Wikidata — Help:Statements

- **Canonical URL:** https://www.wikidata.org/wiki/Help:Statements
- **Status:** Official Wikidata help page (living document)
- **Fetched:** 2026-08-25, HTTP 200
- **Used in:** Chapter 3 (real-world case study of contextualized statements)

## Key Points

- An **item** (Q-id) represents a concept/topic/object; each item has its own
  page and a language-independent identifier.
- A **statement** is how information about an item is recorded; it consists of
  (at least) one **property–value pair** (subject–predicate–object shape).
- The core of a statement without references and ranks is called a **claim**;
  a claim without qualifiers is a **snak**.
- Statements "can be expanded on, annotated, or contextualized" with:
  - **qualifiers** (contextual refinement of the value),
  - **references** (sources),
  - **ranks** (which value(s) to prefer when several coexist).
- Multiple values per property are normal; unknown/no-value are expressible.
- Statements connect items to each other → linked data structure.

## Semantic Contract for Our Chapter 3

- Wikidata is the real-world proof that a production KG treats context as
  first-class: a bare property–value pair is rarely the whole statement.
- Use as the case study alongside our Hanoi example: item = entity with a
  stable opaque identifier (Q-id); statement = assertion; qualifiers/references
  /ranks = context layers.
- Ranks show how a KG can hold competing values (preferred/normal/deprecated)
  without deleting them — a preview of the Chapter 6 epistemic model, mentioned
  but not developed here.
