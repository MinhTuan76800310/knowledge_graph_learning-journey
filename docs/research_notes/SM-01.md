# SM-01: Schema Matching

- **Primary reference:** Rahm, E. & Bernstein, P. A. (2001). "A Survey of Approaches to Automatic Schema Matching." *The VLDB Journal*, 10(4), 334–350.
- **Canonical topic:** Schema matching — identifying semantic correspondences between schema elements
- **Used in:** Chapter 7 (schema alignment)

## Key Points

- Schema matching is the process of identifying that two objects are semantically related across database schemas.
- **Element-level matching:** matches atomic elements such as attributes/columns (e.g., name similarity, data type).
- **Structure-level matching:** matches combinations of elements that appear together in a structure.
- **Schema-level matchers:** use schema information only (names, types, constraints, relationships).
- **Instance-level matchers:** use actual data values to infer meaning.
- **Hybrid matchers:** combine schema and instance techniques.

## Semantic Contract

- Schema matching is a prerequisite for schema alignment/transformation.
- Ch7 teaches the operational concept: source field → candidate mapping → mapping evidence → accepted mapping.
- Do NOT teach the full taxonomy of matching algorithms; focus on the idea that mapping is a decision with evidence, not a one-click operation.
- Do NOT present schema matching as a solved problem; ambiguity is inherent.
