## Key Points

- Neo4j uses the **labeled property graph** model:
  - **Nodes** represent entities, with zero or more **labels** and **properties**
  - **Relationships** connect nodes, have exactly one **type**, direction, and properties
  - **Properties** are key-value pairs attached to nodes or relationships
- Data modeling guidance:
  - Design the model based on domain and use cases
  - Test the model with Cypher queries
  - Refactor for performance when needed
- Key distinction from RDF: properties attach directly to nodes/relationships
  without requiring separate triples or reification.

## Semantic Contract for Chapter 2

- Neo4j's property graph is a distinct data model from RDF.
- The same domain knowledge maps differently into each model.
- Neo4j-specific behaviors (internal IDs, schema indexes) must be distinguished
  from the generic property graph concept.
